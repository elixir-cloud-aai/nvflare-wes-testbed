The first release of the testbed, which ran a federated learning job with NVIDIA FLARE through a GA4GH WES, with one client per site as a GA4GH TES task, over the TES of two ELIXIR Nodes, the FI Node on Rahti and the CZ Node at CERIT-SC, with LS Login tokens, on 2026-11-24. It brings the thin WES with the FL server beside it, the client and probe tasks, a Helm chart for the hub, the synthetic test set and jobs for two to four sites, a plain FedAvg workflow without an FL framework, the tests from a laptop to real Nodes, and a [report](https://github.com/elixir-cloud-aai/nvflare-wes-testbed/blob/v0.1.0/docs/outcomes/report.md) of the results, gaps and draft proposals for TES. The image of all participants is published as `docker.io/elixircloud/nvflare-wes-testbed:0.1.0`, scanned and signed. A sandbox: never for production, and never for real data.

## Features

- Run an NVFlare job through a thin WES, with the FL server beside it and one client per site as a TES task, on local Funnel instances, also through proTES (#1, #2)
- Host the synthetic test set at fixed commits, for real sites (#6, #21)
- Probe a TES node for what a client needs, and answer probes on the FL port between runs (#2, #23, #46, #47)
- Run the hub with Compose, behind a reverse proxy, and on Rahti with a Helm chart (#24, #26, #27, #29)
- Let each site make its own key and send only a signing request over a one-time link (#15, #30)
- Check callers of the WES against a trusted OIDC issuer, such as LS Login (#43)
- Send a token, a token file or OAuth 2.0 tokens to the TES of each site, renewed as needed (#35, #39)
- Run FedAvg as a plain workflow of TES tasks, without an FL framework (#14, #50)
- Run the job with three or four sites (#53, #54)
- Route tasks through proTES with a gateway token and backend IDs (#57, #58)
