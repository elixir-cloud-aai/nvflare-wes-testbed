## Text for the M4.5 report

A short text for the report of milestone M4.5 of ECP work package 4, whose agreed result is a report based on the GA4GH Cloud AI/ML Working Group. It's a draft, like the rest of this page, from the local runs, the three dress rehearsals, the probes and the run over two Nodes above; the [Report](report.md) has the details. The text for the report itself is written in [generic-issues#83](https://github.com/elixir-cloud-aai/generic-issues/issues/83).

**Question.** Can a federated learning job with NVIDIA FLARE (NVFlare) run through the GA4GH Workflow Execution Service (WES), with its participants scheduled as tasks through the GA4GH Task Execution Service (TES) of each site, as the services of ELIXIR On-Cloud offer them? The testbed takes every shortcut it can, and [lists them](../testbed/shortcuts.md).

**What ran, on what.** A WES run, through a thin WES of the testbed, with the FL server beside the WES and one NVFlare client per site as a TES task ([option B1](../testbed/options.md#b1-server-beside-the-wes)):

- **Locally,** on laptops, 2026-11-04 and 2026-11-11: two Funnel instances as sites, directly and through the TES gateway proTES, with mutual TLS between participants. Clients only dial out, and no data of a site reaches the hub: only model updates do. With synthetic data, the federated model reached a holdout accuracy of 0.975, against 0.825 and 0.875 for the sites alone ([Local runs](../tests/index.md#local-runs)). Since then, sites make their own keys and send only signing requests, and the WES takes only callers with a token of a trusted OIDC issuer.
- **On Rahti,** the Kubernetes service of CSC, 2026-11-12, 2026-11-16 and 2026-11-19: the hub, deployed with its Helm chart, and both sites as tasks on one TESK without authentication, in the same cluster. All three runs ended `COMPLETE`, with the NVFlare job `FINISHED:COMPLETED`; in the third, the hub sent an LS Login access token to the TES for each site, which that TESK ignored (rows above).
- **At the FI and CZ Nodes,** 2026-11-24: run `ae7742f2`, with site 1 on the FI Node's TESK on Rahti and site 2 on the CZ Node's TESK at CERIT-SC, both checking one LS Login access token, ended `COMPLETE`, with the NVFlare job `FINISHED:COMPLETED` and a holdout accuracy of 0.975, against 0.825 and 0.875 for the sites alone, as locally. The CZ Node's tasks reached the hub across organizations; nothing inbound was needed at either site. An earlier run that night, with both sites on the FI Node's TESK, failed, as an executor couldn't attach its task's volume ([G13](gap-analysis.md#g13)).
- **At the DE Node,** 2026-11-21: probes of two TES deployments that check tokens, submitted with an LS Login access token. A Funnel ran the probe, but its tasks got out to the hub neither on the FL port nor on 443; a TESK failed before the probe ran, at its own access to Kubernetes (rows above).

**What didn't run.** No TES run by a partner: both TES of the run are run by the testbed's maintainers, and both are TESK. The DE Node couldn't join, as its tasks have no way out to the hub. No proTES on a real node, no third site, no other TES implementation, no run longer than one token's lifetime. So far, this is a proof of concept across two Nodes, and an analysis of what's missing, not a service.

**What's missing.** TES has no service-like tasks (an address, a name and a port that others reach), no time limits, no way to hand a secret to a task outside its records, and no way to pin a task to a site by a property of the site rather than by an address. The FL server therefore runs outside TES, at a hub with a public port. See the [Gap analysis](gap-analysis.md), the [Open questions](open-questions.md), and the draft [Proposals](proposals.md) for TES.

**What this does not deliver.** ELIXIR Cloud is not "available" for federated learning in the sense of the milestone:

- **Authentication:** the WES trusts one issuer, every caller gets the same role in NVFlare, and the hub calls the TES of each site with one user's token from its sites file, not with one exchanged from the caller's for each site and run, and doesn't renew it.
- **Tenants:** one run at a time, kept in memory only, with no separation of users, studies or projects.
- **Sites' control:** sites run whatever job comes. There's no job approval, no site policy and no privacy filter of NVFlare; the data of the test set comes from public URLs that the WES chooses; and the hub, not the site, decides which sites take part.

Each of these is in [Shortcuts and hacks](../testbed/shortcuts.md), with the proper way.
