# Open questions

!!! note "Draft"
    Section 5 holds draft outcomes and proposals, for further consideration, and only what test results support. The questions below come from the local runs, from the three dress rehearsals on Rahti, with the hub and both sites in one cluster, from the probes at the DE, FI and CZ Nodes ([#3](https://github.com/elixir-cloud-aai/nvflare-wes-testbed/issues/3)), and from the run over the FI and CZ Nodes on 2026-11-24 ([Report](report.md)). Whatever is added here stays a draft: it gets finalized elsewhere.

Questions that the tests leave open, or raise. The questions for the tests themselves are in each [test](../tests/index.md).

| Question | Raised by | Answer |
|---|---|---|
| Does a TES task at a partner node get out to the hub's FL port, 30002 on Rahti, or to 443, and through what? | Node probe and [T8](../tests/t8-real-sites.md) on Rahti, 2026-11-12 and 2026-11-16, both in the hub's own cluster; [G11](gap-analysis.md#g11) | Answered for three nodes, without anything in between. FI and CZ Nodes, 2026-11-24: tasks got out on 30002, and the run over both passed ([Report](report.md#first-multi-site-run)); the FI Node's tasks from inside the hub's cluster (hairpin), the CZ Node's from outside. DE Node, 2026-11-21: a Funnel task got out on neither 30002 nor 443 (timeout), so that node can't take part as it stands. Whether these nodes let tasks out on 443 is untested, as the hub's address for the FL port publishes only that port |
| Does the probe's `open` on Rahti say anything about other nodes? | Node probe on Rahti, 2026-11-12 | No. The task reached the hub's public address from inside the same cluster: its traffic went out and back in (hairpin). The port also answered a plain connection from outside the cluster. The first task at another node, at the DE Node on 2026-11-21, didn't get there; tasks at the CZ Node, at another organization's infrastructure, did on 2026-11-24: that's the first question above |
| Does the federated model reach the holdout accuracies of [T1](../tests/t1-simulator.md) on real sites? | T8 on Rahti, 2026-11-12 and 2026-11-16: both runs ended with the NVFlare job `FINISHED:COMPLETED`, without the accuracies recorded | Yes: run `ae7742f2` over the FI and CZ Nodes, 2026-11-24, reached 0.975, against 0.825 and 0.875 for the sites alone, as in T1 |
| How long does a task take to start at a node, and do the job's timeouts allow for it? | T8 on Rahti, 2026-11-12 and 2026-11-16: start times weren't recorded | At the FI and CZ Nodes, 2026-11-24: within 1 s of a task's creation, well within the WES's start timeout of 3 minutes. Open for nodes with queues, and for bigger images |
| Can the hub get tokens for the TES of a partner node from a real identity provider, and renew them during a run? | `tests/tokens_test.py`, with a mock provider only ([G5](gap-analysis.md#g5)) | Partly answered: on 2026-11-19, the hub sent a static LS Login access token to a TESK on Rahti for each site, which didn't check it; on 2026-11-21, a Funnel and a TESK at the DE Node accepted such a token for a probe task. On 2026-11-24, both TESKs of the FI and CZ Nodes checked one LS Login access token of one user, and the run passed ([Report](report.md#first-multi-site-run)). Renewal during a run is untested, and isn't set up on Rahti: an access token lives about an hour |
| Has any real node a way to give a task an address, a name and a port that others reach? | [T5](../tests/t5-server-task.md), local, 2026-11-04 and 2026-11-11 ([G1](gap-analysis.md#g1)) | Open: no partner operator has answered it, as both TES of the run are ours ([Report](report.md#of-the-sites)) |
| Does the direct run also work through proTES and a TES that checks proTES' tokens? | [T4](../tests/t4-protes.md), local only | Open: the [stretch goal](../testbed/index.md#goals) ([#18](https://github.com/elixir-cloud-aai/nvflare-wes-testbed/issues/18)) |
| Is the hub's 2 GiB memory limit on Rahti enough for more than the test set's job? | T8 on Rahti, 2026-11-12: it ran within the limit ([What differed on Rahti](../setup/real-sites.md#what-differed-on-rahti)) | Open for bigger jobs and more sites; models and performance are out of [scope](../testbed/index.md#scope) |
