# Test set

One minimal job and tiny, made-up data.

| What | Where | Source | Licence |
|---|---|---|---|
| Data of up to four sites, and a holdout set: 40 rows each, two features and a label | `data/` | Generated by `generate.py`, from a seeded random number generator and a fixed linear rule. Describes nothing and nobody. | Apache-2.0, as this repository |
| Job: logistic regression with NumPy, federated averaging over 5 rounds, one job per number of sites | `job/logreg-fedavg/` (two sites), `job/logreg-fedavg-3/`, `job/logreg-fedavg-4/`, exported from `job_src/` | Written for this repository, following the `hello-numpy` example of [NVFlare](https://github.com/NVIDIA/NVFlare) | Apache-2.0 |
| Comparison with models trained at one site alone | `evaluate.py` | Written for this repository | Apache-2.0 |

**Public or synthetic data only, tiny, with its source and licence stated. No clinical data and no data from Trusted Research Environments, ever, not even as an example.**

The sites see different parts of the feature space, so a model trained at one site alone generalizes badly. Each share `site-<k>.csv` covers a range of the feature `x2`, which the label depends on:

| Share | Range of `x2` | Holdout accuracy of a model trained on it alone |
|---|---|---|
| `site-1.csv` | -2 to -0.2 | 0.825 |
| `site-2.csv` | 0.2 to 2 | 0.875 |
| `site-3.csv` | -2 to -1 | 0.925 |
| `site-4.csv` | 1 to 2 | 0.900 |

A run with n sites takes the first n shares, one per site, and the job for n sites. Expected holdout accuracy of the federated model:

| Sites | Shares | NVFlare job | Federated |
|---|---|---|---|
| 2 | `site-1.csv`, `site-2.csv` | `logreg-fedavg` | 0.975 |
| 3 | and `site-3.csv` | `logreg-fedavg-3` | 0.975 |
| 4 | and `site-4.csv` | `logreg-fedavg-4` | 1.000 |

The plain FedAvg workflow ([T10](../docs/tests/t10-fedavg.md), `workflow_url=logreg`) takes any number of sites and gets the same accuracies. `evaluate.py` compares the federated model with a model trained on each share in `data/`, also those that weren't in the run, and fails if it doesn't beat them all; with `--expect`, it also fails if the federated accuracy isn't the one given.

The job of NVFlare takes exactly as many sites as it's built for, and the WES refuses a run with another number: FedAvg of NVFlare 2.9 asks a random subset of `num_clients` clients each round, so with more sites than that, some would miss rounds, and with fewer, the job never starts.

Real sites fetch their share from public URLs: see [Real sites](../docs/setup/real-sites.md#the-test-set).

To regenerate the data and the jobs, which gives the same files:

```sh
docker compose --profile test build flare-image
docker run --rm -u "$(id -u):$(id -g)" -e HOME=/tmp -v "$PWD/testset:/testset" nvflare-testbed:local \
    sh -c 'cd /testset && python generate.py --shares 4 && cd job_src \
    && for n in 2 3 4; do python job.py --export-to /testset/job --rounds 5 --sites "$n" || exit 1; done'
```

`generate.py` without `--shares` writes the first two shares and the holdout set, as it did before there were more: the holdout set is drawn before shares 3 and 4, so it's the same for any number.
